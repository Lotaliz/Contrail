# SAVER：按每张图的证据分布，调整“相关”与“不重复”的取舍

## 先理解它用在哪里

**场景：** 给视觉语言模型一张图片和一个问题，让它生成答案。图片已经经过完整视觉编码，变成许多代表不同位置的视觉 token。SAVER 从中留下指定数量，希望减少语言模型随后处理图片的计算。它在语言模型早期层选择 token，正文没有明确到第几层，不能直接归为“主干入口前剪枝”。它也没有减少前面的视觉编码器计算。（§4.1–4.3）

**问题：** 只留下与问题最相关的位置，可能选中很多相似区域；只追求不同区域，又可能把预算花在无关背景上。把两者按固定比例混合，也未必适合每张图。例如，“杯子上的字是什么”可能集中在一小块区域，而“有多少人在过马路”需要看多个位置。这个例子用于解释动机，并非论文展示的定量结果。（§1、§3；示例为本笔记说明）

**主要办法：** 先估计问题相关的视觉位置是集中还是分散，再据此调节相关性和多样性的权重，最后逐步选出一组 token。**每张图改变的是选择偏好，保留数量仍由外部指定。** 因此，sample-aware 不代表自动预测每张图需要多少 token，也不等于本项目 Cx 的全局/局部预算分配。（§4）

最直接的结果是：LLaVA-1.5-7B 从576个视觉 token 留下64个时，作者报告七项任务的平均相对性能为96.5%。这是各任务相对于未剪枝模型的归一化均值，**不是回答准确率96.5%，也不是每项任务都只损失3.5%。** 部署证据比质量证据薄：效率表没有交代硬件、计量单位和完整计时范围，无法据此确定真实端到端收益。（表1、表4）

## 主要概念是什么意思

| 概念 | 在这篇论文中的意思 |
|---|---|
| 相关性 relevance | 一个视觉位置与当前问题的文字表示有多接近；是特征相似度，不是该位置对正确答案的已验证贡献。 |
| 多样性 diversity | 尽量少选重复内容，同时让保留集合能代表其余视觉内容。既涉及“不相似”，也涉及“有代表性”。 |
| 固定预算 | 指定留下 $K$ 个视觉 token；SAVER 在这个数量内选择位置。 |
| 文本中心 WTC | 将问题中的文字向量加权平均，得到一个代表问题的向量；权重来自各文字向量的长度。 |
| 空间分散程度 GIP | 先找最相关的少量视觉位置，再用这些位置坐标的协方差行列式描述其二维分布。不是由人工标注得到的物体框。 |
| 图像内部差异 | 视觉 token 之间平均有多不相似，用来调整空间分散信号的影响强度。不是图像清晰度或政策风险分数。 |
| 无需训练 | 不更新视觉语言模型权重；仍有校准数据、归一化范围及超参数，不能理解成完全无需数据和调参。 |

概念依据：§3–4。下文“作者报告”均指论文结果；本轮没有运行模型或复现选择器。

## 为什么作者认为固定混合不够

§3先把相关性与多样性按权重 $\theta$ 混合，$\theta$ 越大越重视多样性。图1在三个任务上展示不同的合适权重：POPE约0.9、GQA约0.7、MMBench约0.6，同一任务内不同样本的偏好也不一样。这支持“一个固定权重可能不适合所有输入”，但不构成所有数据上必然如此的证明。（§3、图1，PDF第3页）

这里有两种离线挑选方式，必须与实际部署分开：

- 任务级最优权重由评测指标选择，需要知道评测表现。
- 样本级 oracle 权重用**真实答案的平均负对数似然 NLL**选择：让模型在已知正确答案的条件下打分，哪种权重使正确答案更容易出现，就选哪种。部署时不知道正确答案，不能直接使用这个 oracle。

实际 SAVER 用后面的空间分散程度来估计选择偏好，没有在推理时读取真实答案。论文没有给出其预测权重与 oracle 权重的逐样本相关性或误差，也没有证明更低的答案 NLL 必然带来更高的最终准确率。（§3–4；未报告项为本次证据核查）

## 方法：怎样从问题和图片选出 token

### 1. 用问题的文字中心给视觉位置打相关分

文字 token 的向量越长，参与平均的权重越高。加权平均得到文本中心后，计算每个视觉 token 与这个中心的余弦相似度，作为相关分。作者认为这能突出承载内容的词，并避免读取注意力矩阵，因而便于与 FlashAttention 配合。（§4.2）

这是一种简单的整体文字表示。它没有显式建模“哪个词与哪个区域对应”，向量长度也不是普遍成立的重要性标签。正文对特征来源的描述还不完全一致：§4.1/4.2提到早期或浅层语言表示，§4.3又强调不依赖语言模型中间状态。**具体读取哪一层、视觉与文字如何进入相同维度，以及对应部署接口，仍需实现澄清。** 不能仅凭“不读注意力图”推断完全不执行语言模型前缀。（§4.1–4.3）

### 2. 看最相关的位置，是聚在一起还是散在多处

取相关分最高的约2%位置作为锚点，使用它们在原图网格上的二维坐标。坐标协方差矩阵记为 $\Sigma$，空间量为：

$$
G=\det(\Sigma).
$$

直观上，相关位置在两个方向上都分散，$G$ 往往更大；集中在小区域时则较小。作者希望据此判断：这次需要集中保留局部证据，还是覆盖更多内容。（§4.3）

**这个量只是代理信号。** 例如，位置沿一条很长的细线分布，协方差行列式仍可能接近零；因此不能把它直接理解为“证据占据的实际面积”或证据充分性。该例是对公式的数学解释，论文没有提供这类退化分布的专项实验。

作者还计算整张图视觉特征的平均差异 $D$，将 $G$ 和 $D$ 按校准集范围归一化，再计算权重：

$$
\theta=\operatorname{sigmoid}(k\,\widetilde D\,\widetilde G+b).
$$

这里 $k,b$ 控制映射，带波浪号表示归一化后的量。论文另有控制多样性内部取舍的 $\gamma$。这些量不由模型权重训练获得，但仍需要设置；校准子集规模、来源、默认 $k,b$ 等细节未完整给出。（§4.3、§5）

### 3. 每选一个位置，都重新考虑“还缺什么”

SAVER 先算视觉 token 两两之间的相似度，再逐个加入候选，直到达到 $K$ 个。每轮会同时考虑：这个 token 是否相关、是否与已经选中的内容重复，以及加入它能多代表多少尚未覆盖的内容。后两项分别对应“新颖性”和“代表性”，由 $\gamma$ 调节。（§4.4、算法1，PDF第4页）

因此，它不是先给每个 token 一个永远不变的最终分数，再一次性取前 $K$ 个。选中集合变化后，新增一个 token 的价值也会变化。最后保留原来的视觉特征，没有通过重编码局部图片补回细节。（§4.4）

计算代价也不能忽略：正文方法需要完整的两两视觉相似度矩阵，以及多轮选择。避免注意力图不等于选择器零开销；论文未拆出矩阵构建、贪心选择、同步和实际压紧序列各自的耗时。空集合时最大相似度如何初始化等实现细节也未完整展开。（算法1、表4；缺口为本次核查）

## 实验到底支持了什么

### 主表：固定预算下，平均质量较强，但并非每项都最好

LLaVA-1.5-7B 有576个视觉 token。表1包含 GQA、MMBench、MME、POPE、ScienceQA、TextVQA、OCRBench 七项任务；分数保留原表尺度，不同列不能直接相加。

| 配置 | GQA | MMBench | MME | POPE | ScienceQA | TextVQA | OCRBench | 平均相对性能 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 未剪枝，576 token | 61.9 | 64.3 | 1862 | 85.9 | 69.5 | 58.2 | 297 | 100% |
| SAVER，192 token | 61.2 | 63.8 | 1855 | 85.7 | 69.3 | 57.8 | 300 | 99.6% |
| SAVER，128 token | 60.9 | 63.6 | 1811 | 85.5 | 69.2 | 57.2 | 287 | 98.4% |
| SAVER，64 token | 60.0 | 61.8 | 1758 | 83.8 | 68.9 | 56.2 | 282 | 96.5% |

同为64 token时，PruneSID、DivPrune 的平均相对性能分别为93.8%、93.7%，SAVER平均更高。但 POPE 上 DivPrune 为85.8，高于 SAVER 的83.8；ScienceQA 上 DART 为69.8，也高于68.9。因而更准确的说法是“该表的平均取舍较好”，而非“所有任务都优于已有方法”。VisionZip 有缺失的 OCRBench 单元格，跨基线均值的缺失项处理没有充分交代。（表1）

表2/3还测试 LLaVA-NeXT 和 Mini-Gemini：前者最多2880 token，保留640/320时平均相对性能98.5%/96.2%；后者576 token，保留128/64时98.1%/94.7%。这两表使用六项任务，并含 SEEDBench，与表1任务集合不同。不能把三种模型的均值直接排成同一质量榜。（表2/3）

正文列出八个不同评测任务，但主表不是八任务均值；没有完整列出每个任务的样本数、拆分、生成配置和软件环境。没有实测本库已收录的 CDPruner 或 SheafPrune，不能据此推断胜过这两者。（§5.1、表1–3）

### 消融：自适应权重有平均增益，幅度需要准确理解

表5只用 POPE、GQA、MMBench 三项任务：

| 选择方式 | POPE | GQA | MMBench | 三任务平均相对性能 |
|---|---:|---:|---:|---:|
| 只看相关性 | 73.7 | 56.3 | 61.9 | 91.0% |
| 只看多样性 | 83.4 | 58.7 | 59.9 | 95.0% |
| 固定混合 | 84.0 | 59.5 | 60.4 | 95.9% |
| SAVER 自适应混合 | 83.8 | 60.0 | 61.8 | 96.9% |

这里自适应比固定混合高**1.0个百分点的三任务归一化均值**，但 POPE 略低。它不能和主表七任务的96.5%混用；论文没有报告置信区间、跨随机种子稳定性，也没有单独证明文字向量长度加权一定优于其他文字汇聚方式。（表5）

图3在 LLaVA-NeXT 的 POPE 上扫描 $\gamma$，中间取值通常更好，合适取值还随预算改变。这进一步说明“无需训练”仍包含超参数取舍，而非一组常数已被证明适用于所有场景。（图3）

## 与当前 visual-token-pruning / Cx 的关系

**可以借鉴的部分：** SAVER把“相关位置在空间上如何分布”变成选择偏好的输入，为低成本空间线索提供一个具体例子。它也提醒我们，用已知正确答案得到的最优选择只是离线上界，实际部署必须换成不读答案的信号。相关性与多样性需要在同预算下比较，而不是仅凭名称推断联合必然更好。（§3–4；项目判断）

**迁移边界：** Cx目前关注每张图的全局预算、至多一个局部区域，以及政策条件下的任务代价。SAVER只在完整视觉编码后、给定预算内选位置，不预测全局/局部收益，不决定裁图分辨率，也没有证明小区域包含充分安全证据。一般问题相关性不能直接替代政策条款相关性。（本项目判断，参照§4–5）

用户先前报告的小图约400个视觉 token并非本轮实测；若在这个规模照用2%锚点，仅约8个位置，其空间统计可能不稳定。这是待验证假设。文字中心是否保留否定词、条件条款和多对象关系，同样需要政策变化和像素删除对照，而非以余弦分数本身认定安全贡献。
