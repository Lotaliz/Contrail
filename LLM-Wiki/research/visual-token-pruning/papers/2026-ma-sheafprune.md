# SheafPrune：先看问题，再用图结构修正视觉 token 的保留顺序

## 先理解它用在哪里

**场景：** 给视觉语言模型一张图片和一个问题，让它生成答案。图片先经过完整的视觉编码器，再转换成语言模型能够接收的一串视觉 token。SheafPrune 在这些步骤之后、语言模型第一层之前，只保留一部分视觉 token，希望减少语言模型读取图片的时间。它没有提前减少视觉编码器的计算，也不负责生成政策或判断内容是否违规。（§1、§3.1、图2）

**问题：** 同一张图，不同问题需要的证据可能不同。只给每个区域单独打分，可能留下许多重复区域，也可能漏掉不起眼的文字或细节。把相似区域连成图、让分数在图中传递，是一种办法；但邻居多的区域也可能只是因为“连接多”而积累高分。论文重点研究怎样限制这种传递，以及怎样修正连接数量带来的偏向。（§1、§3.4）

**主要办法：** 先用问题与图像的关系形成初始分数，再让分数只沿选定的视觉关系传递，最后按邻居数量修正排名，留下预算允许的最高分 token。作者训练约450万参数的选择器，视觉编码器、投影器和语言模型都保持冻结。（§3、附录I/M）

这篇最值得注意的证据是：**固定配置下，将初始分数全部设成相同，仍保留了大部分效果。** 因而目前更强的证据指向图结构与排名修正的作用；问题相关的学习分数确有增益，但不能据此说它是主要收益来源。主表又采用逐评测点挑选最优超参数的方式，应与固定部署配置分开看。（§4.3、表2/10、附录M）

## 主要概念是什么意思

| 概念 | 在这篇论文中的含义 |
|---|---|
| 视觉 token | 编码器对一个图像位置或区域产生的向量。这里选择的是已算出的向量，不是直接裁掉原图像素。 |
| 保留率与预算 | 保留率 $\rho$ 决定留下多少个可剪 token；剪枝率 $p=1-\rho$。预算是外部指定的，模型会据此改变选择，但不会自行判断每张图需要多少预算。 |
| 图、边与邻居 | 每个视觉 token 是一个节点；特征足够相似的两个节点连边，允许交换分数。它们不一定在图片上相邻。 |
| 图传播 | 节点把分数按边的权重分给邻居，重复若干次，让排名考虑区域之间的关系。 |
| 度与度修正 | 度是一个节点有多少个邻居。修正是把传播后的分数除以邻居数量的某个幂，减少“邻居多就容易排前面”的偏向。不是保证每种图上都完全消除偏向。 |
| sheaf | 数学中的“层结构”，与神经网络的第几层无关。此处主要启发是：文字与视觉先分别转换到一个可比较的空间，再按指定关系传递信息。实际视觉分数传播使用普通图转移矩阵，并非一个新的一般性 sheaf 扩散算法。 |
| prefill 与 decode | prefill 是生成前读取输入、建立后续生成状态的阶段；decode 是之后逐个生成答案 token 的阶段。论文的大加速数字主要属于 prefill。 |
| RA 性能保留率 | 每个任务的剪枝分数除以未剪枝分数，再对十个任务取平均。RA为90%并不是答案准确率90%，也不保证每个任务都保留90%的能力。 |

概念依据：§3.1–3.6、附录A/E/K。一个理解示例：如果有400个可剪 token，指定保留10%，就选40个；原本必须保留的结构 token 另计。所以它是在给定预算内选位置，尚不是本项目 Cx 的逐样本预算预测。

## 方法：从输入到输出

### 1. 先明确预算和允许读取的文字

每个样本独立计算保留数量：

$$
k=\min\{|\mathcal C|,\max(1,\lceil\rho|\mathcal C|\rceil)\}.
$$

$\mathcal C$ 是允许剪掉的视觉位置。图像换行等结构位置不在这个集合中，会额外保留。文本包括系统提示、已经结束的对话和当前问题，排除当前目标答案、未来对话、图像占位符和 padding。因此，训练时选择器不能偷看它要帮助模型回答的答案。（§3.1/3.3、附录B/C/H）

选择器外接一个小型双向文本编码器，让它理解词序；保留率也作为输入条件。这样，同一个训练好的选择器可以面对不同预算，调整分数和选择结果。**预算条件不等于预算预测。**（附录C，式13–15）

### 2. 把问题的重要性传给视觉区域

文字与视觉各经过自己的归一化和线性映射，进入128维的比较空间。投影后距离越小，关系权重越大。对于精确单位向量，这种距离等价于余弦相似度的变换；作者也明确承认这一关系，没有声称名称本身带来额外表达能力。（§3.2/3.3、附录A/D）

每个文字 token 只向关系最强的一部分视觉 token 传递分数。文字自身也有一个学习出的重要性权重；两者合起来形成“这个视觉位置与当前文字有多相关”的分数。随后把它与视觉特征的向量长度混合，得到初始分数。向量长度只是视觉侧先验，不能直接当成真实任务贡献；表10的单独先验表现也很弱。（附录D/E、表10）

### 3. 在视觉图里传递分数

视觉图与上述文字—视觉图分开建立。先算所有有效视觉 token 对的余弦相似度，再用每张图自己的分位数阈值，保留约5%的非对角关系，并加入自连接。因为使用同一个全图阈值，连接支持是对称的，但不同节点可以有不同数量的邻居。这里只保留指定关系上的传播权重，未连边的位置权重严格为零。（§3.4、附录E）

默认传播3步：

$$
s^{(\ell+1)}=s^{(\ell)}T,\qquad
f_i=\frac{s_i^{(t)}}{d_i^\delta}.
$$

$s$ 是一行分数，$T$ 表示每个节点向邻居分出的权重，$d_i$ 是节点 $i$ 的邻居数，$\delta$ 控制修正强度，默认1。

**为什么已经归一化，还要再除邻居数？** 每个节点“分出去”的权重总量相同，不代表每个节点“收进来”的总量相同。很多节点都指向同一个区域，它仍可能积累更多分数。度修正是在接收之后调整排名，和传播时的行归一化解决不同问题。（§3.4，式5；附录E）

传播与度修正都不要求最终选中的位置覆盖整张图。特征相似也不等于位置连续，所以这套方法没有天然给出一个局部框。（§3.4、附录Q）

### 4. 训练时保留完整形状，让选择器收到梯度

训练的前向选择是硬 Top-$k$：确实只允许选中的视觉位置充当注意力的 key；未选位置的注意力概率被乘零，然后重新归一化。反向时用平滑的 sigmoid 近似传递梯度，称为直通估计器。它是训练硬选择的一种近似办法，不意味着 Top-$k$ 本身可微。（§3.5、附录F，式32–36）

完整视觉序列仍保留在训练计算路径中。模型使用目标答案的下一词交叉熵来训练选择器，梯度经过冻结语言模型返回；冻结权重不等于不执行前向或反向计算。没有教师蒸馏损失，也没有区域标注监督。它不属于此前用户排除的在线策略蒸馏论文。（§3.5、附录F/M）

### 5. 部署时真正删掉未选 token

推理时只运行一次选择器，在语言模型第一层前收集保留的视觉 token，再由缩短的序列进入全部语言层。token顺序、attention mask和原始位置编号一起保留；使用多维位置编码的模型还需保留原坐标，不能简单重新从零连续编号。（§3.5、附录G）

这是实际缩短序列，因此能减少后续语言模型计算；视觉编码器和投影器已经完整执行，其成本不会消失。原文报告训练门控与物理删除的fp32最大logit差异为 $5.147\times10^{-3}$，超过作者使用的 $10^{-3}$ 严格等价阈值，所以没有宣称两条路径数值完全等价。全部精度与效率主结果使用物理删除路径。（附录G/J）

## 训练和评测设置

作者在LLaVA-NeXT-8B上训练选择器，再将同一检查点用于Qwen2.5-VL-7B、InternVL3-8B、LLaVA-1.5-7B，不额外重训练。这个说法指训练权重复用，**不代表各评测点都使用同一套推理超参数**。（§4.1、附录M）

| 项目 | 原文设置与定位 |
|---|---|
| 文本选择器 | 256维瓶颈、两层双向注意力、4个头，最长1024个文字token；比较空间128维；约450万参数（附录C/I，表3） |
| 第一阶段 | 强视觉信号子集，约0.3个epoch，保留率0.9（附录M，表7） |
| 第二阶段 | 按来源加权的779K指令混合，约2个epoch；四步分别从0.5/0.3/0.1均匀采样保留率，接着额外一步使用0.9（附录M，表7/8） |
| 来源权重 | OCR、图表、细粒度定位等2.5，一般VQA等1.0，图像较次要的描述/对话0.5；这是采样权重，不是数据占比（表8） |
| 优化 | AdamW，学习率 $2\times10^{-4}$，weight decay 0.01，warm-up 1000步，梯度裁剪1.0；有效batch 64–128，bf16、eager attention，两张96GB GPU；未列GPU型号（附录M） |
| 预算范围 | 训练保留率0.9/0.5/0.3/0.1；评测保留率0.9/0.7/0.5/0.4/0.3/0.2/0.1，同一权重覆盖未直接采样的中间预算（§4.1、表7） |

十个任务包括ChartQA、DocVQA、TextVQA、HR-Bench 4K/8K、GQA、VQAv2、MMBench-EN、POPE和MME。表4明确各自样本数与split，例如DocVQA validation 5,349条、TextVQA validation 5,000条、GQA testdev-balanced 12,578条。指标随任务分别采用relaxed accuracy、ANLS、VQA accuracy、选择题准确率、F1或MME分数；不是十个任务都算同一种准确率。（§4.1、附录K，表4）

基线包括Random、G-Prune、FastV、SparseVLM、PyramidDrop、ToMe；另在LLaVA-1.5比较FasterVLM、VisionZip、PruMerge。全部在作者统一的评测与答案提取流程中重跑。后几种方法只测一个主干，不能把空白结果当成它们不支持其他主干；也未实测所有既有选择器。（附录L，表5/6）

## 结果：分别看固定配置和挑选最优的主表

### 主表说明了什么

作者在每个评测点从 $\delta\in\{0,0.5,1,2\}$ 中选择最好结果，得到22/28个主干—预算点的最高RA。附录M明确：现有汇总表**不能证明这个选择来自独立验证集**，也不能证明固定一个 $\delta$ 部署就会复现这条曲线。因此，主表描述已测试参数里的性能上沿，不是无需调参的部署保证；当前材料也不足以反过来断言一定发生了测试集泄漏。（§4.1、附录M/O）

LLaVA-NeXT保留30%时，SheafPrune的RA为98.71%，G-Prune为97.86%，ToMe为91.61%；三者prefill分别55.3、52.8、52.6 ms。SheafPrune的质量更好，但在这个预算约多花5%的时间。DocVQA从未剪枝的72.6变为67.2，G-Prune为64.8，说明平均保持率高也不意味着每项任务完全无损。（§4.2、表1/9）

保留10%时，LLaVA-NeXT的RA为90.42%，Qwen2.5-VL为84.60%；但在LLaVA-1.5被FasterVLM/VisionZip超过，在InternVL3被G-Prune超过。LLaVA-NeXT的DocVQA此时只有46.6，相比72.6明显下降，而TextVQA为60.0，相比66.7下降较小。不要用90.42%的平均RA遮住文档细节任务的损失。（§4.2、表9）

### 固定配置更能回答哪些部件有用

表2/10在LLaVA-NeXT固定 $t=3,q_v=0.05,\delta=1$，只改变对应部件。下列为保留10%时的结果；“文字任务”是ChartQA、DocVQA、TextVQA的平均相对保持率。

| 配置 | 十任务RA | 文字任务保持率 | 可以支持的判断 |
|---|---:|---:|---|
| 完整方法 | 89.39% | 74.97% | 固定配置的参考，不等于主表90.42% |
| 初始分数全部相同 | 88.19% | 73.32% | 只少1.20和1.65个百分点，图结构能保留大部分收益 |
| 不做度修正 | 72.80% | 38.30% | 相比完整方法少16.59个百分点，修正非常关键 |
| 稠密传播变体 | 72.68% | 38.10% | 改变允许传播的关系后，效果明显下降 |
| 只按度排名，不传播 | 81.38% | 57.09% | 邻居数量有信息，但不能替代完整算法 |
| 随机选择 | 73.38% | 39.20% | 固定预算的基础对照 |

“初始分数相同”不等于比较了训练与不训练的检查点，所以不能据此断言训练无用。去掉问题相关项或视觉先验时，RA分别为86.40%和85.00%，都弱于两者混合；效果存在交互，不能将差值简单相加作为各模块的因果贡献。（附录M/P，表10）

稠密变体把非边位置的logit写成0，再对所有位置做softmax，所以它们得到 $\exp(0)=1$ 的正权重。它同时改变连接范围和归一化，不是只改分母，也不是在证明官方G-Prune存在这一错误。图1/4/5的可视化同样没有单独隔离问题条件的作用；图4还使用5步传播，而默认消融为3步，不能混成同一设置。（§4.3、附录P/R/S；PDF第9页）

## 加速到底节省了什么

| LLaVA-NeXT设置 | 未剪枝 | 保留30% | 保留10% |
|---|---:|---:|---:|
| prefill时间，含选择成本 | 149.4 ms | 55.3 ms | 29.0 ms |
| 报告的prefill加速 | — | 2.70× | 5.15× |
| decode吞吐 | 66.5 token/s | 68.3 token/s | 67.3 token/s |
| 含视觉处理的FLOPs减少 | 0 | 66.4% | 84.0% |

依据表9。**5.15×属于prefill，不是完整答案的总时延加速。** decode变化很小；84.0%是计算量减少，不是墙钟时间减少84%。选择器开销报告为未剪枝prefill的2.6%，在更短的LLaVA-1.5序列上达到7.2%；后者保留10%只得到2.11× prefill加速。（§4.2、附录J/K/N）

计时与精度评测分开：从GQA、ChartQA、DocVQA、HR-Bench 4K各取15条，共60条；每条3次预热、10次CUDA event重复，并强制生成32个token测decode。**60条评测样本不是已说明的推理batch size。** 本文没有充分列出推理硬件型号、软件revision、batch/padding策略或选择器各阶段计时，应作为复现缺口保留。（附录K）

对于LLM内部剪枝的基线，作者使用单token生成计时，再加主干对应的输出头修正，例如LLaVA-NeXT为+6.53 ms。表中是修正后的prefill量，不能直接当作统一的原始首token时延。速度按逐样本比值汇总，也不要用两组独立汇总的中位数自行重算加速。（附录K）

方法还显式构建完整的视觉两两相似度矩阵，辅助空间为

$$
O(N_t^2+N_tN_v+N_v^2).
$$

其中 $N_t,N_v$ 是文字和视觉序列长度。图传播稀疏不代表建图已经是线性成本；视觉序列很长时，二次方工作区仍可能占主导。实际获益取决于省下的语言模型计算是否超过选择器开销。训练只做一次，不能据“450万参数”推定推理代价一定很小。（§3.6、附录J）

比较预算时，作者对内部剪枝采用跨层平均保留率，而非最后一层剩多少token。必须记录不同层的长度和结构token；例如一个10%的候选预算，实际可能保留11.6%的全部视觉位置。PyramidDrop/SparseVLM在当前分阶段实现中有25%的跨层平均保留率下限，对应缺失预算点不是零效果。（附录K/L）

## 局限、失败条件与对当前项目的判断

**原文直接证据：** 强剪枝下最终子集可能集中在少数位置。附录Q表13用8×8网格衡量覆盖：GQA在10%保留率下，SheafPrune覆盖0.417，随机为0.500；345个候选只留下约35个，而4096个候选可以留下约410个。相同百分比的绝对证据量不同，不能直接把高分辨率上的表现外推到用户报告平均约400个视觉token的本项目小图；该平均数本轮未复测。跨任务同时改变内容与token化，表13不能证明覆盖不足就是跨主干例外的唯一原因。

**作者主张的边界：** 本文提出受sheaf启发的比较与图排序设计，未证明一般性的语义保留或空间覆盖保证；附录E的长期传播结论只对给定图及其连通分量成立，不能据此说默认3步已经收敛或与问题无关。附录O也明确，汇总分数不足以做配对显著性、训练种子方差或多重比较检验。

**本项目判断／尚未验证的迁移假设：**

- 可以参考“同一选择器接收预算条件”和“限制关系后再修正排名”。但SheafPrune在给定预算里选token，[[LLM-Wiki/changes/2026-10-20-resolution-plan-and-superseded-ideas-cleanup.md|Cx（历史方案，已删除）]]要预测逐样本全局与单局部预算，职责不同；它没有预测追加局部视图的条件收益。
- 当前政策指导方案需要证明政策改变后保留的证据也有效改变。本文图可视化和小幅初始化增益还不足以提供这一证明。均匀初始化、去文字、打乱文字、固定预算只改位置，是值得考虑的对照；这里只提出判断，不执行或规定新实验。
- 可以把度修正理解为避免重复特征群挤占预算的一种启发，但它不识别安全证据，也不直接产生一个可解释局部框。政策Guard的漏报、误报和未见政策效果仍需独立证据。
- 与 [[LLM-Wiki/research/visual-token-pruning/papers/2025-zhang-cdpruner.md|CDPruner]] 都有关问题相关性和冗余；机制分别为图传播排名与条件多样性子集选择。本文没有实测CDPruner，不能建立两者优劣。与 [[LLM-Wiki/research/visual-token-pruning/papers/2026-gao-quietprune.md|QuietPrune]] 的执行位置也不同：SheafPrune不减少视觉塔计算。既有两篇笔记用于定位比较，不代表本轮重新复现。

关联概念：[[LLM-Wiki/concepts/methods/multimodal-token-pruning.md]]。本次把已核验机制与条件加入 [[LLM-Wiki/research/visual-token-pruning/comparison.md|比较]]，不新建concept，不更新正式motivation，不改Cx方案或现有实验状态。
