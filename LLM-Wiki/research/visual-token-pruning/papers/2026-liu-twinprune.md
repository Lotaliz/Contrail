# TwinPrune：分开压缩读图计算和生成时的视觉记忆

## 先理解它用在哪里

**场景：** 视觉语言模型先读取图片和问题，再逐个生成答案。读输入的阶段称为 prefill，之后逐个生成称为 decode。前者有整段视觉序列的计算，后者需要反复读取已存下的 key/value 状态，称为 KV cache。TwinPrune分别处理这两种成本：在读取输入过程中减少视觉 token，在开始生成时进一步删除一部分视觉 KV。（§1、§4）

**问题：** 两处剪枝会影响不同的计算。如果只看由 prefill 最后状态确定的第一个输出，就可能完全看不到后续删除 KV 的影响；如果预先已经删掉大部分视觉 token，继续删缓存也未必还有多少余地。论文既提出一个局部特征差异选择器，也强调两阶段应分别测量。（§3、§6）

**主要办法：** 找出与周围位置不太相似的视觉 token，优先保留；prefill 时再加入覆盖不同特征的选择，decode 时按分数一次性淘汰视觉 KV。它不需要为基础选择器训练新模型，但论文另有带 LoRA 适配的对照，不能把所有结果统称为“完全未经训练”。（§4、表2）

本篇最值得带走的是**评测边界**：在第一个输出已经确定之后才删除缓存，当然不能追溯改变那个输出；这不能证明缓存对后续回答无用。另一个重要限制是，公开 v2 的源文件明确说明**附录被省略**，所以正文引用的完整算法、理论证明、跨模型和联合压缩补充表未能逐项核验。下文将可查看的结果与作者转述分开。（§3、§6；官方TeX源文件 `appendix_refs.tex`）

## 主要概念是什么意思

| 概念 | 在这篇论文中的意思 |
|---|---|
| prefill 剪枝 | 在语言模型某层减少后续需要处理的视觉位置；剪枝层之前仍做完整输入计算。 |
| decode KV 淘汰 | 输入已读完后，删除部分视觉位置存下的 key/value，让后续生成读取更少缓存；不是重新计算一个更低分辨率图片。 |
| “密度” density | 实际分数是某个位置与周围位置的特征有多不同。高分意味着局部变化较大，不是物体数量多，也不保证语义或安全重要。 |
| 最远点选择 FPS | 每次优先选择与已选集合差异较大的位置，让保留内容不要过于相似。这里还加入局部差异分数。 |
| prefill 保留与 decode 保留 | 两个独立比例。decode 的分母是 prefill 后剩下的视觉数量，不一定是原图最初数量。 |
| 原位置与旋转后 key | 部分模型用位置旋转表示顺序。删掉缓存行时保留已有位置含义，不能把剩下的 key 当成新序列重新旋转一遍。 |
| 输出不一致率 | 剪枝输出与未剪枝输出不同的比例。它不等于准确率下降：两者不同也可能一个对、一个错，或都错。 |

概念依据：§3–4。局部差异是明确可计算的信号，但“重要信息”只是作者对它的解释，不应自动当作真实任务贡献。

## 为什么只看第一个输出会漏掉 decode 影响

先设定一个具体过程：模型完成 prefill，算出了第一个输出的分数并选定 $y_1$；**随后**才删除视觉 KV；接下来用剩余缓存生成 $y_2,y_3,\ldots$。如果评测只取 $y_1$，后面的删除就不会改变这个已经确定的结果。这是计算顺序带来的条件性结论。（§3.1）

这个结论有三个边界：

- 必须确认淘汰确实发生在用于评分的那个输出已确定之后，而不是更早修改了 prefill。
- 必须确认评测只读取这个输出。如果先生成解释、前缀或思维链，再抽取后面的答案，即使题目是选择题或 yes/no，也可能依赖后续缓存。
- **prefill 剪枝可以改变第一个输出。** 不能从 decode 的条件性结论推导“首 token 评测也看不到 prefill 剪枝”。正文部分措辞把二者说得过宽，应以真实注入位置为准。

上述边界是对§3计算流程的解释，不由数据集名称单独决定。

表1在 InternVL3.5-8B 上删除全部视觉 KV：MMBench、POPE、ScienceQA 的输出不一致率为0.54%、0.38%、0.20%，TextVQA为45.5%。**45.5%是输出发生变化，不是准确率下降45.5个百分点。** 前三项仍有少量变化，也说明具体实现和评分路径需要进一步解释，不能无证据地归因于浮点误差。（表1，PDF第4页）

图2另展示 TextVQA 在视觉 KV 全删时准确率明显下降，约从0.65降至0.42。图2、表2和表3的未剪枝 TextVQA 基线并不相同，不能把不同实验的起点拼成一条质量曲线。（图2、表2/3）

## 方法：两次压缩各做什么

### 1. 用邻近位置的差异给 token 排序

对一个图像网格位置，比较它与周围位置的余弦相似度：

$$
\rho_i=1-\operatorname{mean}_{j\in\mathcal N(i)}\cos(x_i,x_j).
$$

邻域排除自己，分别使用3、5、7尺度窗口，取多尺度分数的最大值。高分表示这里与附近特征不同，作者希望保留边缘、细节等局部变化。（§4.1）

这不直接读取当前问题或政策条款。若特征取自已经融合文字的语言模型层，仍可能间接受文字影响；因此“没有显式问题分数”与“任何层都绝对不受问题影响”是两件事。后一判断不能仅凭该公式成立。（方法事实及本笔记推断）

### 2. prefill：把局部差异与整体覆盖结合

在指定层 $L$，根据预设剪枝率确定保留数量。先选局部差异最高的 token，再重复选择：与已选集合越不相似、局部差异越大的位置，越容易被加入。正文使用的形式是“到已选集合的最小特征距离＋$\beta$乘归一化局部差异”，默认 $\beta=0.3$。最后按原索引顺序排列保留位置。（§4.1–4.2）

图3还画出把未保留内容合并到锚点的过程。但正文没有把分配规则、合并权重及合并后分数如何复用完整写出，详细算法指向缺失的附录A。**现有公开材料足以理解选择原则，尚不足以无歧义重建全部合并实现。** 不能把示意图自行补成一种已核实的具体加权平均。（图3，PDF第5页）

剪枝越晚，越多前缀层已经付出完整计算。正文说明未选位置的 KV 从后续层删除，并不意味着剪枝层之前已经生成的全部缓存和计算都自动消失；每层具体缓存映射仍应看实现。（§4.2）

### 3. decode：再删一次视觉 KV，文字记忆继续保留

在 prefill/decode 的边界，按同一局部差异分数，一次性保留指定比例的视觉 KV。这里的数量基于 **prefill 压缩后**的视觉 token。文字 KV 保留，已经存在的旋转后 key 和原位置含义也保留；文中要求首个生成位置按原 prefill 长度继续，而不是按缩短后的缓存长度重新编号。（§4.3）

例如，某条后续层路径在 prefill 先保留50%视觉位置，再在 decode 保留其中25%，最终是原视觉位置的约12.5%。这只是解释比例相乘，**不等于整个模型显存降到12.5%**：前缀层缓存、文字及新生成 KV、模型权重都另计。两阶段都发生在完整视觉编码之后，也不会因此节省视觉塔成本。（§4；数量示例为本笔记说明）

### 4. 真正加速还依赖部署实现

作者用 Triton 合并选择过程中的最大值和距离更新，并用 CUDA Graph 缓存重复执行的计算图。正文报告，若每次重新捕获图，约80毫秒的额外成本足以抵消收益；缓存按输入形状及选择参数复用。因此报告的加速包含这种工程条件，不能外推到任意动态形状、冷启动或单张小图。（§4.2）

正文还存在复杂度口径问题：摘要称线性，但§4.2描述预先构建 $N\times N$ 的余弦距离矩阵，并做多轮最远点选择。固定大小邻域的局部分数可以随 $N$ 线性增长，**这并不自动证明完整选择器也线性。** 附录B和完整实现未取得，尚不能核实融合内核是否采用另一种存储/计算安排。（§4.1–4.2）

§4.1给出覆盖半径与输出误差的关系，证明指向附录H。当前材料没有完整假设和证明，不能将该式解释为整个视觉语言模型、更不能作为政策安全的已验证误差保证。正文对最远点选择“达到最小覆盖半径”的强表述也不能仅凭算法形式确认。

## 实验：质量、时间和缓存分别看

### 评测范围与可核验程度

正文涉及七种模型配置：InternVL3.5的2/4/8/38B、Qwen3-VL的2/4B、LLaVA-1.5-7B。表2主要展示 InternVL3.5-8B 的 prefill，对 decode 的表3使用 TextVQA、MMVet、DocVQA；更多模型和联合配置的细表指向未公开附录。不能把摘要的跨七模型结论当作本轮逐表核验完毕。（§5–6）

正文给出 TextVQA 5000样本、MMVet 218样本、DocVQA 5349样本，分别采用 exact match、官方评审和 ANLS。TextVQA 的 exact match 与另一篇论文可能使用的标准 VQA 评分不同，不能只看同名数据集便横向比较。MMBench、POPE、ScienceQA 按作者协议读取首输出；其限制见前文。（§5）

### prefill 主表：平均结果和加速都有适用条件

表2把作者方法写为“CAC (ours)”，正文称 TwinPrune；本笔记按作者行读取，不自行展开 CAC。原表 TPL 列在正文没有完整计算定义，下表不把它等同为真实 FLOPs 或某层入口保留率。

| InternVL3.5-8B 配置 | 作者方法的 TextVQA | 四任务平均 | 作者报告的 prefill 加速 | 需要一起看的对照 |
|---|---:|---:|---:|---|
| 未剪枝 | 0.6493 | 0.8411 | 1.00× | MMBench/POPE/ScienceQA/TextVQA 四项 |
| 第15层剪50% | 0.7195 | 0.8759 | 1.16× | Random 的平均0.8500、加速1.28×；本文质量高，但不是更快 |
| 第3层剪85% | 0.5696 | 0.7894 | 2.67× | ToMe平均0.7626、加速2.07× |
| 第0层剪80% | 0.5793 | 0.8003 | 3.24× | FastV平均0.7892、加速3.58×，TextVQA 0.6149；本文并非每项最好或最快 |

定位：表2，PDF第7页。较早剪枝可省更多语言模型计算，但质量和时间必须一起看。

第3层极端剪枝时，DivPrune/DART 的约0.001分数被作者标为无效输出。故障分类指向缺失的附录S，不能据此认定这两个方法本来几乎没有任务能力，也不能不核对位置编码适配就当作公平性能差距。带 LoRA 的 B3b 是另一组经过适配的配置：第0层剪70%时，作者平均0.8319、TextVQA 0.6385、加速2.14×；LoRA 的完整训练细节不在可取得正文中。（表2、§5）

**3.24×是什么时间？** §4.2报告 RTX A6000 48GB、batch 8、高分辨率12 tile/3072视觉 token，按每样本归属的 prefill 时间从487.7降至150.8毫秒；选择器示例维度4096、保留614。这个结果依赖融合内核及图缓存，不是本项目约400-token小图的实测，也不是从图像输入到完整答案输出的总时延。图捕获、视觉前端等各项是否都进入同一边界，正文没有完整拆解。（§4.2、表2）

表3的保留比例是视觉 KV 保留率。为避免只看“比另一个压缩器好”，同时列出未淘汰基线：

| 方法／视觉KV保留率 | TextVQA | MMVet | DocVQA |
|---|---:|---:|---:|
| 不淘汰 | 0.733 | 0.756 | 0.642 |
| Density，50% | 0.726 | 0.708 | 0.575 |
| Density，25% | 0.697 | 0.634 | 0.466 |
| Density，12.5% | 0.648 | 0.551 | 0.382 |
| H2O，12.5% | 0.552 | 0.497 | 0.347 |
| SnapKV，12.5% | 0.573 | 0.513 | 0.377 |

定位：表3，PDF第9页。Density为按局部差异保留的本文方法，表值保留原尺度。

保留12.5%时，TextVQA比 H2O 高9.6个百分点，但比未淘汰低8.5个百分点；MMVet和DocVQA相对未淘汰分别低20.5和26.0个百分点。因此“压得更好”仍可能伴随明显任务退化。DocVQA在50%/25%保留时，SnapKV的0.577/0.469略高于本文0.575/0.466，也不存在所有任务所有预算都最佳。（表3）

正文还承认 V-norm 在 MMVet 的25%保留配置高于 Density 4.8个百分点，但细表6未公开。图4中未压缩 TextVQA 标记约65%，与表3的73.3%起点不同；图注和图例对38B展示的表述也不完全一致。**没有相同实验配置的说明，不能据图4和表3混算“压缩反而提升质量”。** 图中视觉 KV 的 MiB 也不是整模型峰值显存。（§6.1、图4）

### 两阶段合用是否比只做一阶段更好

§6.2的文字报告：在相同 KV 预算下，联合压缩并不总能优于单阶段；prefill已经很激进时，不同 decode 选择方法的差距可缩到约1个百分点内。这支持将两阶段收益分开评估，但详细表8/10在省略的附录中。这里仅记录**作者的正文陈述**，没有将其当作本轮核验过的完整质量—成本网格。

## 对当前 Cx 有什么启发

**最直接的是实验设计。** 先写清干预在哪里、发生在第几个输出之前，再选择能感受到该干预的任务。若政策 Guard 的标签只由已经算出的首输出决定，之后删 KV 而标签不变是预期结果，不构成视觉记忆无用或剪枝安全的证据。另一方面，在视觉输入或语言模型早期删 token，仍然可能影响该首输出。（§3；本项目判断）

**方法信号可以作为候选，不能替代政策价值。** 局部特征变化有可能帮助保留小细节，但背景纹理也可能变化很大；小危险物体也不一定与邻居差异突出。要迁移到 Cx，仍需同图政策变化、删除/保留区域、固定全局预算下添加局部区域等对照。论文没有给出固定误报率的漏检、unsafe→safe翻转或政策配对安全结果。（本项目待验证假设）

**成本不应跨阶段混算。** 视觉塔已经完整执行，prefill剪枝与decode淘汰都不能直接替代 Cx 的输入分辨率规划。跨样本动态形状是否能复用图缓存、短输入选择器是否划算，也需在真实工作负载核验。这里不引入额外批处理方案，也不改动当前实验和正式 motivation。

可对照 [[LLM-Wiki/research/visual-token-pruning/papers/2026-huang-saver.md|SAVER]] 的逐样本选择偏好、[[LLM-Wiki/research/visual-token-pruning/papers/2026-ma-sheafprune.md|SheafPrune]] 的给定预算选择。三者均不能只按剩余 token 数推算端到端加速。
